# NeuroCare API

A small FastAPI service that serves my NeuroCare migraine-subtype classifier (XGBoost, 7 classes, 23 coded symptom features) as a REST API. It is packaged with Docker and tested with pytest and GitHub Actions.

> **Research prototype.** The model was trained on a small public dataset (400 records, 80-record test set). It is not a medical device and must not be used for clinical decisions. The 7-day LSTM from my NeuroCare project is **not** served here, because its labels were simulated.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Service status and whether the model loaded |
| GET | `/features` | The 23 feature names, in training order |
| POST | `/predict` | Predict the migraine subtype from coded symptoms |
| GET | `/docs` | Interactive Swagger UI (generated by FastAPI) |

An example request body is in `examples/sample_request.json`. The response contains `predicted_class`, `confidence` and the probability of each class.

`confidence` is the model's own probability for its top class. It is not the chance that a migraine attack will happen, and small models are often over-confident. The API gives no medical advice.

## What I built and checked
- Input validation: missing or unexpected features are rejected, and `/predict` returns 503 if the model could not be loaded.
- 7 automated tests that use small dummy model files, so they run without my real model.
- Verified locally against the real saved model: `/health` reports `"model_loaded": true` and `/predict` returns a prediction with class probabilities.
- A Dockerfile that runs the app as a non-root user and has a health check.
- A GitHub Actions workflow that runs the tests, builds the image and smoke-tests the running container.

## Run it locally (Windows)
Use **Python 3.11 or 3.12**. The versions are pinned to match the saved model, and scikit-learn 1.6.1 has no ready-made package for Python 3.13 or 3.14, so pip would try to compile it and fail.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m pytest -v
python -m uvicorn app.main:app --reload
```

Then open http://localhost:8000/docs, or:

```
curl http://localhost:8000/health
curl -X POST http://localhost:8000/predict -H "Content-Type: application/json" -d @examples/sample_request.json
```

## Run it in Docker
```
docker build -t neurocare-api .
docker run -p 8000:8000 neurocare-api
curl http://localhost:8000/health
```

## Model files
`artifacts/` holds four files saved from my training notebook:

- `migraine_model.pkl`: the fitted classifier (an imbalanced-learn pipeline with SMOTE + XGBoost; SMOTE is skipped at prediction time)
- `migraine_scaler.pkl`: the fitted StandardScaler
- `migraine_label_encoder.pkl`: the class names
- `migraine_feature_columns.pkl`: the feature names, in training order

They were saved with scikit-learn 1.6.1 and XGBoost 3.2.0, and pickled models only load reliably with the same versions, which is why `requirements.txt` pins both. To replace the model, retrain, then use `export_artifacts_snippet.py` to save the four files.

Python pickle files can run code when they are loaded, so only load pickles you trust. These four are my own. Do not swap in files from unknown sources.

## Limitations
- Small dataset (400 records) with a very dominant class. The 80-record test set has only a few examples of the rare subtypes, so the performance estimate is noisy.
- The input features are coded values (for example duration 1 to 3), not free text, and the model has not been validated on real patients.
- High confidence on one example does not mean the model is clinically reliable.
